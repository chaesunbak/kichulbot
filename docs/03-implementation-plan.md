# Implementation Plan

## 목적

이 문서는 MVP를 실제로 구현하기 위한 작업 순서와 완료 기준을 정리한다.

Product Brief, MVP Spec, Technical Design은 방향과 설계를 정하는 문서다. 이 문서는 개발 중 체크리스트로 사용한다.

## 구현 원칙

- 한 번에 한 기능 흐름을 끝까지 연결한다.
- 관리자 등록 기능을 먼저 만든 뒤 사용자 풀이 기능으로 넘어간다.
- 배포 환경에서 테스트할 수 있는 상태를 빠르게 만든다.
- 펫, 미션, 포인트, 해설, 소셜 로그인은 구현하지 않는다.

## Phase 0. 프로젝트 기반 구성

목표: Next.js, NestJS, Postgres, Prisma, Tailwind, Docker 배포 기반을 만든다.

작업:

- `apps/web` Next.js 앱 생성
- `apps/api` NestJS 앱 생성
- pnpm workspace 스크립트 정리
- Tailwind CSS 설정
- API Dockerfile 작성
- 로컬 PostgreSQL용 `docker-compose.yml` 작성
- Prisma 설정
- 기본 Health Check API 추가

완료 기준:

- `web`이 로컬에서 실행된다.
- `api`가 로컬에서 실행된다.
- API가 Postgres에 연결된다.
- `/api/health`가 정상 응답한다.

## Phase 1. 인증과 권한

목표: 사용자별 답안 기록을 분리할 수 있는 인증 구조를 만든다.

작업:

- User 모델 구현
- `UserAuthType` 구현
- 게스트 시작 API
- 게스트 access token 발급
- 게스트 사용자의 이메일 계정 전환 API
- 이메일 회원가입 API
- 이메일 로그인 API
- JWT 발급
- `Authorization: Bearer {accessToken}` 인증 처리
- `GET /api/auth/me`
- role 기반 권한 가드
- 관리자 seed 계정 생성
- 이메일 인증 메일은 발송하지 않음
- Web 로그인/회원가입 화면 구현
- Web 게스트 시작 버튼 구현
- Web 인증 상태 저장

완료 기준:

- 사용자가 게스트로 시작할 수 있다.
- 사용자가 회원가입할 수 있다.
- 사용자가 로그인할 수 있다.
- 게스트 사용자가 회원가입하면 기존 기록이 유지된다.
- 로그인한 사용자 정보를 조회할 수 있다.
- `ADMIN`만 관리자 API에 접근할 수 있다.
- access token은 `Authorization` 헤더로 전달된다.

## Phase 2. 문제지와 태그 기반 데이터

목표: 수능 한국사 1개년 문제지를 등록할 수 있는 데이터 기반을 만든다.

작업:

- Exam 모델 구현
- Subject 모델 구현
- Paper 모델 구현
- Tag 모델 구현
- Question 모델 구현
- QuestionTag 모델 구현
- 수능, 한국사, 시대 태그 seed 생성
- 관리자 문제지 생성 API
- 관리자 태그 조회 API
- 관리자 문제지 목록/상세 API
- 관리자 문제지 등록 화면
- 관리자 문제지 목록 화면

완료 기준:

- 관리자 계정으로 문제지를 만들 수 있다.
- 수능/한국사/시대 태그 seed가 생성된다.
- 관리자 화면에서 문제지 목록을 볼 수 있다.

## Phase 3. 문제 이미지 업로드

목표: 관리자가 문제 1개씩 이미지를 업로드하고 정답과 태그를 등록할 수 있게 만든다.

작업:

- Cloudflare R2 버킷 생성
- R2 환경 변수 설정
- API `StorageService` 구현
- 문제 이미지 업로드 API
- 문제 생성 API
- 문제 수정 API
- 관리자 문제 등록 화면
- 관리자 문제 수정 화면
- 이미지 미리보기 구현

완료 기준:

- 관리자가 문제 이미지 1개를 업로드할 수 있다.
- 업로드된 이미지는 R2 public URL로 접근된다.
- 문제에 정답, 선택지 개수, 시대 태그를 저장할 수 있다.
- 20문항짜리 문제지를 등록할 수 있다.

## Phase 4. 내 책장

목표: 사용자가 문제지를 서비스 안의 내 책장에 추가할 수 있게 만든다.

작업:

- UserPaper 모델 구현
- 문제지 목록 API
- 내 책장 추가 API
- 내 책장 조회 API
- 문제지 목록 화면
- 내 책장 화면

완료 기준:

- 로그인 사용자가 문제지 목록을 볼 수 있다.
- 사용자가 문제지를 내 책장에 추가할 수 있다.
- 내 책장에서 추가한 문제지를 볼 수 있다.

## Phase 5. 문제 풀이와 임시 저장

목표: 사용자가 1개년 20문항 문제지를 한 문제씩 풀고, 선택 답안이 임시 저장되게 만든다.

작업:

- AnswerSession 모델 구현
- DraftAnswer 모델 구현
- 풀이 세션 시작 API
- 문제지 풀이 데이터 조회 API
- 문항별 임시 답안 저장 API
- 임시 답안 조회 API
- 한 문제씩 푸는 화면
- 문제 번호 네비게이션
- 선택지 개수 기반 답안 버튼
- 최종 제출 버튼

완료 기준:

- 사용자가 문제지 풀이를 시작할 수 있다.
- 한 번에 한 문제씩 볼 수 있다.
- 답안을 선택하면 임시 저장된다.
- 새로고침 후에도 선택 답안이 복원된다.

## Phase 6. 최종 제출과 결과

목표: 최종 제출 시 정오답을 저장하고 결과를 보여준다.

작업:

- AnswerLog 모델 구현
- 최종 제출 API
- 정오답 계산
- 점수 계산
- 제출 후 DraftAnswer 정리
- 결과 화면 구현
- 틀린 문제 표시

완료 기준:

- 사용자가 20문항 답안을 최종 제출할 수 있다.
- 사용자별 AnswerLog가 저장된다.
- 결과 화면에서 점수, 정답 수, 오답 수를 볼 수 있다.
- 틀린 문제를 확인할 수 있다.

## Phase 7. 태그별 약점 분석

목표: 사용자의 풀이 기록을 시대 태그별로 집계해 약점을 보여준다.

작업:

- 태그별 분석 API
- 풀이 수, 정답 수, 오답 수, 정답률 계산
- 약점 정렬 기준 적용
- 약점 분석 화면 구현

완료 기준:

- 사용자가 시대 태그별 풀이 수를 볼 수 있다.
- 사용자가 시대 태그별 정답률을 볼 수 있다.
- 오답 수가 많은 태그를 확인할 수 있다.

## Phase 8. 매일 갱신되는 오답 문제지

목표: 사용자가 오늘의 오답 문제지를 다시 풀 수 있게 만든다.

작업:

- WrongQuestionSet 모델 구현
- WrongQuestionSetItem 모델 구현
- 오늘의 오답 문제지 생성/갱신 API
- 오늘의 오답 문제지 조회 API
- 오답 복습 세션 시작 API
- 오답 복습 화면 구현

완료 기준:

- 사용자별 오늘의 오답 문제지가 생성된다.
- 최근 풀이 기준으로 틀린 문제가 오답 문제지에 포함된다.
- 같은 날에는 오답 문제지 구성이 유지된다.
- 다음 날 갱신 시 다시 맞힌 문제는 제외될 수 있다.
- 사용자가 오답 문제지를 다시 풀 수 있다.

## Phase 9. 배포

목표: MVP를 Vercel, Render, Render Postgres, Cloudflare R2에 배포한다.

작업:

- Render Postgres 생성
- Render API 서비스 생성
- API Docker 배포 설정
- API 환경 변수 등록
- Prisma migration 배포 설정
- Vercel Web 프로젝트 생성
- Web 환경 변수 등록
- CORS origin 설정
- R2 환경 변수 등록
- 배포 DB seed 실행

완료 기준:

- Vercel에서 Web이 열린다.
- Render에서 API가 열린다.
- API가 Render Postgres에 연결된다.
- API가 R2에 이미지를 업로드한다.
- 배포 환경에서 회원가입부터 오답 복습까지 동작한다.

## Phase 10. MVP Smoke Test

목표: 배포된 MVP의 핵심 흐름을 한 번에 검증한다.

체크리스트:

- 회원가입
- 로그인
- 게스트 시작
- 게스트에서 이메일 계정 전환
- 관리자 로그인
- 문제지 생성
- 20문항 문제 등록
- 문제 이미지 표시
- 사용자 문제지 목록 조회
- 내 책장 추가
- 문제지 풀이 시작
- 문항 선택 시 임시 저장
- 새로고침 후 임시 답안 복원
- 최종 제출
- 결과 확인
- 태그별 약점 분석 확인
- 오늘의 오답 문제지 생성
- 오답 문제지 다시 풀기

## 구현에서 제외

이번 MVP에서는 다음 작업을 하지 않는다.

- 소셜 로그인
- 이메일 인증
- 이메일 발송
- 비밀번호 재설정
- 해설 입력 및 표시
- 선택지 텍스트 저장
- 서술형 답안 입력
- 전체 문제 한 화면 풀이
- 사용자별 커스텀 분류
- 문제지 PDF 생성
- 실제 파일 다운로드
- AI 해설 생성
- 펫, 미션, 포인트

## 첫 개발 목표

첫 번째 개발 목표는 Phase 0부터 Phase 3까지다.

여기까지 끝나면 관리자가 배포 환경에서 수능 한국사 1개년 20문항을 등록할 수 있다. 그 다음 사용자 풀이 기능으로 넘어간다.
